# 주요 기여 및 문제 해결

## 1. CS 기반 현장 프로그램의 웹 전환 제안 및 구현

### 배경

기존 현장 프로그램은 VB.NET 기반 클라이언트 환경으로 운영되고 있었으나 담당 개발자 퇴사로 인해 유지보수 부담이 증가하고 있었음.

신규 프로젝트 진행 과정에서 장기적인 유지보수 관점의 대안이 필요

### 담당 역할

* 웹 기반 현장 프로그램 전환 제안
* 현장 프로그램 기능 개발
* 후배 개발자 기술 지원 및 개발 표준 정리

### 구현 내용

* 웹 기반 현장 프로그램 기능 구현
* 바코드 스캐너 연동 기능 구현

### 성과

* 사내 최초 웹 기반 현장 프로그램 구축
* 웹 개발 인력 중심 유지보수 가능 환경 확보
* 이후 프로젝트 표준 구조로 채택

---

## 2. 프레임워크 4.0 전환 및 서비스 계층 중심 구조 적용

### 배경

프로젝트와 함께 사내 프레임워크를 3.0에서 4.0으로 전환하는 작업을 병행.

기존 Stored Procedure 중심 구조에서 서비스 계층 중심 구조로 전환이 필요

### 담당 역할

* 서비스 계층 전환 개발
* 트랜잭션 처리 구조 적용
* MyBatis 매퍼 구조 개선

### 구현 내용

* 프로시저 중심 로직을 서비스 계층으로 이관
* 서비스 레이어에서 트랜잭션 범위 및 롤백 처리
* MyBatis 매퍼를 테이블 단위로 분리
* 화면 서비스와 공통 테이블 서비스 구조 적용
* 복잡한 프로시저 로직을 단순 쿼리 기반 구조로 개선

### 성과

* 트랜잭션 처리 흐름 명확화
* 코드 재사용성 향상
* 유지보수성 개선

---

## 3. 요구사항 불일치로 인한 재작업 문제 개선

### 배경

프로젝트 참여자별로 요구사항 이해 수준이 달라 개발 완료 후 설계 변경 및 재작업이 반복적으로 발생

### 담당 역할

* 정기 회의 제안
* 요구사항 정리 및 변경사항 공유
* 이해관계자 의견 조율 지원

### 구현 내용

* PM·실무 개발자·업무 담당자 참여 회의 제안
* 플로우 기반 요구사항 검토
* 모듈 단위 완료 후 검증 및 피드백 반영
* 변경사항 문서화 및 공유

### 성과

* 반복 재개발 감소
* 요구사항 해석 차이 최소화
* 일정 내 프로젝트 납기 완료 기여

## 4. 브릿지 테이블 설계 및 구현을 통한 데이터 정합성 확보

### 문제

기존 DB 구조는 설비 1대와 작업지시 1건만 연결 가능한 구조였으나, 신성산업은 여러 작업지시를 동시에 처리하는 배치 생산 환경으로 운영됨.

이로 인해 설비 가동률 집계 시 중복 계산 문제가 발생

### 담당 역할

* 데이터 모델 분석
* 브릿지 테이블 설계 및 구현
* 가동률 계산 로직 개선

### 구현 내용

* 설비-작업지시 관계 관리용 브릿지 테이블 설계
* 작업 시작 시 작업지시 매핑 로직 구현
* 작업 종료 및 비가동 처리 로직 구현
* 설비 가동률 집계 로직 개선

### 성과

* 배치 생산 환경 지원
* 설비 가동률 데이터 정합성 확보
* 운영 데이터 신뢰도 향상
